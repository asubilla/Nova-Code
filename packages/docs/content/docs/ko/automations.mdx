# 자동화

자동화는 트리거를 다단계 워크플로에 연결합니다. Webhook이나 프로젝트 이벤트가 프롬프트와 셸 명령으로 구성된 파이프라인을 시작하며, 자동 승인 규칙, 예산, 재시도, 승인 수신함이 함께 제공됩니다. **설정 → Nova Code → 자동화**에서 설정합니다.

## 트리거

트리거는 워크플로(또는 예약 작업)를 시작하는 것입니다. 두 종류입니다:

- **Webhook** — Nova Code 외부에서 오는 HTTP POST입니다. URL과 시크릿을 받으며, 시크릿은 `X-Webhook-Secret` 헤더로 보냅니다. CI, 다른 머신의 cron, 다른 도구의 버튼에 적합합니다.
- **이벤트** — 여기서 이미 일어난 일입니다. 세션이 끝났거나, 세션이 실패했거나, 예약 작업이 실패했습니다.

각 트리거를 하나의 워크플로(또는 예약 작업)에 연결한 뒤 저장합니다. **Fire**는 트리거를 수동으로 실행하여 외부에서 호출하기 전에 연결을 확인합니다.

## 워크플로

워크플로는 순서가 있는 단계 목록입니다. 각 단계는 다음 중 하나입니다:

- **Prompt** — 세션에 메시지를 보냅니다(새로 만들거나 기존 id 재사용). 세션이 유휴 상태가 될 때까지 기다릴 수 있습니다.
- **Shell** — 프로젝트 디렉터리에서 명령을 실행하며 타임아웃이 있습니다.

각 단계에는 고유한 **실패 시** 정책이 있습니다:

- **stop**(기본) — 실행을 끝내고 오류를 기록
- **continue** — 오류를 기록하고 계속
- **retry** — 워크플로의 재시도 설정에 따라 지수 백오프로 재시도

선택적 **예산**(`max tokens`, `max attempts`)은 단계 중간에 실패하는 대신 `budget_exhausted`로 실행을 깔끔하게 멈춥니다. **Run**은 워크플로를 즉시 실행하며, 감사 로그가 각 단계를 기록합니다.

## 자동 승인 규칙

**Policy**의 규칙은 에이전트가 권한을 요청할 때 어떻게 처리할지 결정합니다. 각 규칙은 도구와 내용 패턴(`*` 및 `?` 와일드카드)으로 일치합니다. 처음 일치하는 활성 규칙이 이깁니다:

- **accept** — 자동 승인
- **deny** — 거부(보류됨, 거부로 표시됨)
- **hold** — 당신에게 남김, 승인 수신함에 기록됨

자동화 정책은 외부 안전망보다 먼저 실행되며, 첫 번째 비어 있지 않은 판정이 이깁니다.

## 승인 수신함

보류된 권한은 승인 수신함에 쌓입니다. 하나씩 승인하거나 거부하거나, 여러 개를 선택해 일괄 처리하세요. 각 결정은 OpenCode에 회신하여 대기 중인 에이전트가 즉시 계속(또는 중지)합니다.

## 감사 로그

모든 실행은 항목을 추가합니다: 무엇이 발동했는지, 각 단계의 결과, 정책 판정, 에스컬레이션. 항목은 추가 전용이며 상한이 있어 로그가 무한히 자라지 않습니다. 감사 쓰기 실패는 경고로 기록되며, 그것을 만든 실행을 결코 실패시키지 않습니다.

## 기억하세요

- Webhook 시크릿은 서버 밖으로 나가지 않으며 저장 후 다시 표시되지 않습니다.
- 트리거와 워크플로는 Nova Code 서버가 실행 중일 때만 발동합니다.
- 잘못된 트리거나 워크플로는 읽을 때 건너뛰며, 다른 것을 절대 막지 않습니다.
