# 自動化

自動化はトリガーをマルチステップのワークフローにつなぎます。Webhook またはプロジェクトイベントが、自動承認ルール・予算・リトライ・承認インボックス付きのプロンプトとシェルコマンドのパイプラインを開始します。**設定 → Nova Code → 自動化**で設定します。

## トリガー

トリガーはワークフロー（またはスケジュールタスク）を開始するものです。2 種類あります。

- **Webhook** — Nova Code 外部からの HTTP POST。URL とシークレットを受け取り、シークレットは `X-Webhook-Secret` ヘッダーで送ります。CI、別マシンの cron、別ツールのボタンに適しています。
- **イベント** — ここで既に起きたこと。セッション終了、セッション失敗、スケジュールタスク失敗。

各トリガーをワークフロー（またはスケジュールタスク）1 つに向けて保存します。**Fire** はトリガーを手動実行し、外部から呼び出す前に配線を確認できます。

## ワークフロー

ワークフローは順序付きのステップ列です。各ステップは次のいずれかです。

- **Prompt** — セッションへメッセージを送信（新規作成または既存 id の再利用）。セッションがアイドルになるまで待機できます。
- **Shell** — プロジェクトディレクトリでコマンドを実行（タイムアウト付き）。

各ステップには個別の**失敗時**ポリシーがあります。

- **stop**（既定）— 実行を終了してエラーを記録
- **continue** — エラーを記録して続行
- **retry** — ワークフローのリトライ設定に従い指数バックオフで再試行

任意の**予算**（`max tokens`、`max attempts`）はステップ途中で失敗せず、`budget_exhausted` で綺麗に停止します。**Run** はワークフローを即時実行し、監査ログが各ステップを記録します。

## 自動承認ルール

**Policy** のルールは、エージェントが権限を求めたときの挙動を決めます。各ルールはツールと内容のパターン（`*` と `?` のワイルドカード）で照合します。最初に一致した有効なルールが勝ちます。

- **accept** — 自動承認
- **deny** — 拒否（保留され、拒否としてマーク）
- **hold** — あなたの判断待ち、承認インボックスに記録

自動化ポリシーは外側のセーフティネットより先に走り、最初の非空判定が勝ちます。

## 承認インボックス

保留された権限は承認インボックスに入ります。1 件ずつ承認・却下するか、複数選択して一括処理できます。各判断は OpenCode に返信し、待機中のエージェントがすぐに続行（または停止）します。

## 監査ログ

各実行はエントリを追記します。何が発火したか、各ステップの結果、ポリシー判定、エスカレーション。エントリは追記専用かつ上限付きで、ログが無制限に伸びることはありません。監査書き込み失敗は警告として記録され、その実行を失敗させることはありません。

## 注意

- Webhook のシークレットはサーバーを出ず、保存後に再表示されません。
- トリガーとワークフローは Nova Code サーバーが動いているときだけ発火します。
- 不正なトリガーやワークフローは読み込み時にスキップされ、他をブロックしません。
