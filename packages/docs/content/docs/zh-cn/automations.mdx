# 自动化

自动化把触发器连接到多步工作流：Webhook 或项目事件启动一条由提示词和 Shell 命令组成的流水线，附带自动批准规则、预算、重试和审批收件箱。在 **设置 → Nova Code → 自动化** 中配置。

## 触发器

触发器是启动工作流（或计划任务）的东西。两种类型：

- **Webhook** — 来自 Nova Code 外部的 HTTP POST。你会得到一个 URL 和密钥；把密钥放在 `X-Webhook-Secret` 头里。适合 CI、另一台机器上的 cron，或另一个工具里的按钮。
- **事件** — 这里已经发生的事：会话结束、会话失败，或计划任务失败。

把每个触发器指向一个工作流（或计划任务），然后保存。**Fire** 手动运行触发器，方便在外部调用之前先检查连线。

## 工作流

工作流是有序的步骤列表。每个步骤要么是：

- **Prompt** — 向会话发送消息（新建或复用已有 id），可选择等待会话空闲。
- **Shell** — 在项目目录中运行命令，带超时。

每个步骤有自己的**失败时**策略：

- **stop**（默认）— 结束运行并记录错误
- **continue** — 记录错误并继续
- **retry** — 按指数退避重试，使用工作流的重试设置

可选的**预算**（`max tokens`、`max attempts`）会以 `budget_exhausted` 干净地停止运行，而不是在步骤中途失败。**Run** 立即执行工作流；审计日志记录每一步。

## 自动批准规则

**Policy** 下的规则决定 agent 请求权限时的行为。每条规则按工具和内容模式匹配（`*` 和 `?` 通配符）。第一条匹配的已启用规则获胜：

- **accept** — 自动批准
- **deny** — 拒绝（挂起并标记为拒绝）
- **hold** — 留给你，记入审批收件箱

自动化策略在外层安全网之前运行；第一个非空裁决获胜。

## 审批收件箱

被挂起的权限进入审批收件箱。可以逐条批准或拒绝，也可以选中多条批量处理。每次决定都会回复 OpenCode，等待中的 agent 立即继续（或停止）。

## 审计日志

每次运行都会追加一条记录：什么触发了它、每一步的结果、策略裁决和升级。记录只追加并有上限，日志永远不会无限增长。审计写入失败会记为警告，永远不会让产生它的运行失败。

## 请记住

- Webhook 密钥不会离开服务器，保存后不再显示。
- 触发器和工作流只在 Nova Code 服务器运行时触发。
- 一个坏的触发器或工作流在读取时会被跳过；它永远不会阻塞其他。
